Recap: Regular Languages
In the last few lectures we explored regular languages:
▶ Described by DFAs, NFAs, and regular expressions
▶ All three are equivalent: they describe the same class of
languages
▶ Closed under complement, union, intersection, concatenation,
star
▶ Pumping Lemma: a tool for proving languages are not
regular
Two kinds of formalism:
▶ Recognisers (machines): DFA / NFA read a string, accept or
reject
▶ Descriptors: Regular expressions describe a pattern

2/1

Recap: The DFA
A DFA is a 5-tuple (Q, Σ, δ, q0 , F ).
What are the five parts?
▶ Q: finite set of states
▶ Σ: input alphabet
▶ δ : Q × Σ → Q: transition function
▶ q0 ∈ Q: start state
▶ F ⊆ Q: accepting states
Key properties:
▶ Deterministic: exactly one transition per state per symbol
▶ DFA = NFA in power (but NFAs can be exponentially smaller)
▶ NFA acceptance: ∃ at least one accepting path

3/1

The Limits of Regular Languages

Finite automata are a very weak model of computation:
▶ A DFA has a fixed, finite number of states
▶ It has no memory other than which state it is in
▶ It cannot count, and cannot remember an unbounded amount
of information
Example: D = {0n 1n | n ≥ 0} is not regular.
A DFA would need to count the 0s and remember that count when
checking the 1s, but it only has finitely many states.

Why Context-Free Grammars?

So far we have described languages using machines (DFAs, NFAs).
Now we take a different approach: instead of recognising strings,
we generate them.
Context-free grammars appear everywhere:
▶ Programming languages: syntax of Python, Java, C
▶ Compilers: parsing source code into syntax trees
▶ Natural language: sentence structure (noun phrases, verb
phrases)

Formal Definition

A context-free grammar is a 4-tuple G = (V , Σ, R, S).
Compare with a DFA: (Q, Σ, δ, q0 , F ).
a CFG correspond to?

What do the four parts of

▶ V : finite set of variables (non-terminals)
▶ Σ: finite set of terminals (alphabet), with V ∩ Σ = ∅
▶ R: finite set of rules, each of the form A → w
where A ∈ V and w ∈ (V ∪ Σ)∗
▶ S ∈ V : the start variable

14/1

Derivation Notation
▶ u⇒v

(“u yields v ”)

u can become v by one substitution step

▶ u ⇒∗ v

(“u derives v ”)

u can become v in zero or more steps

▶ A sequence u ⇒ w1 ⇒ w2 ⇒ · · · ⇒ v is called a derivation
of v from u
Language of G :
L(G ) = {w ∈ Σ∗ | S ⇒∗ w }
All strings of terminals that can be derived from the start variable.

Context-Free Languages
Definition: A language A is context-free if there exists a CFG G
such that A = L(G ).
Why “context-free”?
Every rule has a single variable on the left-hand side:

A→w

You can replace A regardless of what surrounds it.
It doesn’t matter what’s to the left or right of A.
In contrast, a context-sensitive
grammar allows rules like
αAβ → αw β,
where the replacement depends on the
surrounding symbols α, β.

Not context-free:
B1 → 1B
B can only be replaced
when followed by 1

Ambiguity in Natural Language
Consider the English sentence:

“The boy saw the girl with the mirror.”
How many different meanings can you find?
1. The boy used the mirror to see the girl (instrument)
2. The boy saw the girl who had the mirror (possession)
In natural language, ambiguity is common and resolved by context.
In programming languages, ambiguity is undesirable: code should
have exactly one meaning.

24/1

Ambiguity: Definition and Resolution
Definition: A grammar is ambiguous if some string has two or
more different parse trees (equivalently, two or more leftmost
derivations).
▶ G4 (E → E + E | E × E | (E ) | a) is ambiguous
▶ G2 (E → E + T | T , T → T × F | F , F → (E ) | a) is
unambiguous
▶ Same language, different grammars!
How did G2 avoid ambiguity?
Multiple variables (E , T , F ) force a unique grouping that encodes
operator precedence. This is a standard compiler design technique.

Inherently ambiguous: A CFL is inherently ambiguous if every
grammar for it is ambiguous. These exist, but are rare.

The Stack

A stack is a last-in, first-out (LIFO) data structure:
▶ Push: add a symbol to the top
▶ Pop: remove and read the top symbol
▶ Can only access the top (not deeper elements)
▶ Unbounded: can grow as large as needed
Practical trick: Push a special bottom-of-stack marker ($) at
the start. If you ever see $ on top, the stack is effectively empty.
(The formal definition doesn’t include “test if empty” as a primitive, but
$ gives you the same effect.)

PDA for {ww R | w ∈ {0, 1}∗ }: The Idea
Remember G3 generated {ww R }. Now let’s build a
machine for the same language.
Problem: The machine reads left to right. It
doesn’t know how long the input is, so it can’t
know where the middle is.

G3 :
S → 0S0
S → 1S1
S →ε

Strategy (using non-determinism):
1. Read symbols, push each onto the stack
2. At each step, non-deterministically guess: am I
at the midpoint?
3. If yes: switch to popping, matching each
popped symbol against the input
4. Accept if the stack is empty at the end
Many branches guess wrong and fail. Only the
correct guess leads to acceptance.

Non-determinism in PDAs
When a PDA forks non-deterministically, the entire machine
replicates:
▶ Current state, head position, and the full stack are all copied
▶ Each branch proceeds independently
▶ The machine accepts if any branch reaches an accept state
Key difference from finite automata:
DFA vs NFA
DPDA vs NPDA

Same power (DFA = NFA)
Different power (DPDA ⊊ NPDA)

{ww R } requires non-determinism: the machine must guess the
midpoint.
A deterministic PDA cannot recognise this language.

PDA: Formal Definition
A pushdown automaton is a 6-tuple (Q, Σ, Γ, δ, q0 , F ).
Compare with a DFA: (Q, Σ, δ, q0 , F ).

What’s new?

▶ Q: finite set of states
▶ Σ: input alphabet
▶ Γ: stack alphabet (can differ from Σ)
▶ δ : Q × Σε × Γε → P(Q × Γε ): transition function
▶ q0 ∈ Q: start state
▶ F ⊆ Q: accepting states
Where Σε = Σ ∪ {ε} and Γε = Γ ∪ {ε}.
P(·) = power set ⇒ non-determinism (multiple possible moves).

34/1

Reading the Transition Function

δ(q, a, c) = {(r1 , d), (r2 , e)}
In state q, reading input a, popping c from the stack:
▶ Move to r1 and push d, or
▶ Move to r2 and push e
Shorthand for transitions:
Read a from input
Pop b from stack
Push c onto stack

a, b → c

(a = ε: don’t read)
(b = ε: don’t pop)
(c = ε: don’t push)

35/1

PDA Acceptance
A PDA accepts string w if there exists some sequence of
transitions that:
1. Starts in q0 with an empty stack
2. Reads all of w
3. Ends in a state in F
Just like NFAs: at least one accepting path is enough.
The language of a PDA P:
L(P) = {w ∈ Σ∗ | P accepts w }

The Key Theorem: CFG = PDA
Theorem: A language is context-free if and only if some
pushdown automaton recognises it.
Two directions:
▶ CFG → PDA: Given a CFG, build a PDA for the same
language.
We will prove this direction.
▶ PDA → CFG: Given a PDA, build a CFG for the same
language.
True, but the construction is more involved. (Sipser Ch. 2.2;
know the fact, not the proof.)

Together: A is a CFL ⇐⇒ ∃ CFG G with A = L(G ) ⇐⇒ ∃
PDA P with A = L(P).

40/1

CFG → PDA Construction
Given a CFG G , build a PDA that simulates a leftmost derivation
on the stack.
Key insight: Only substitute variables when they are at the top of
the stack. When a terminal appears on top, pop it and match it
against the input immediately.
Algorithm:
1. Push the start variable onto the stack
2. If top is a variable: replace it with a right-hand side
(non-deterministically choose which rule to apply)
3. If top is a terminal: pop it and match against the next input
symbol
(reject this branch if they disagree)
4. If the stack is empty: accept

Today’s Journey
▶ Regular languages are limited: a DFA has no memory beyond
its current state
▶ Question: What if we give a finite automaton some memory?
▶ Two answers, two perspectives:
▶ CFGs: generate strings via substitution rules, derivations,
parse trees
▶ PDAs: recognise strings using a DFA + stack

▶ The big result: CFGs and PDAs are equivalent. They
describe exactly the same class of languages: the
context-free languages.
▶ Every regular language is context-free, but not vice versa.
