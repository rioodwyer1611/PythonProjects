Task 1.
For each of the following languages, determine whether it is Turing-decidable and/or
Turing-recognizable. Justify your answers.
1. HALT2048 = {⟨M, w⟩ | TM M halts on input w within 2048 steps}
2. A2048 = {⟨M, w⟩ | TM M accepts input w within 2048 steps}

Solution.
We analyze each language by asking whether there is a Turing machine that always halts
and decides membership.
1. HALT2048 is Turing-decidable, and therefore also Turing-recognizable.
On input ⟨M, w⟩, a decider can simulate M on input w for at most 2048 steps.
• If M halts within those 2048 steps, accept.
• If M has not halted after 2048 steps, reject.
This procedure always halts after a finite, fixed number of simulation steps, so it is a
decider.
Since every decidable language is also recognizable, HALT2048 is also Turing-recognizable.
2. A2048 is Turing-decidable, and therefore also Turing-recognizable.
On input ⟨M, w⟩, simulate M on w for at most 2048 steps.
• If M enters an accept state within those 2048 steps, accept.
• Otherwise, reject.
Again, this algorithm always halts because the simulation is bounded by 2048 steps.
Therefore A2048 is decidable, and hence also recognizable.

Task 2.
Someone claims to have constructed a decider H for the acceptance problem
ATM = {⟨M, w⟩ | M is a TM that accepts w}.
Their construction is as follows:
H = “On input ⟨M, w⟩:
1. Simulate M on input w.
2. If M accepts, accept.
3. If M rejects, reject.
4. Otherwise, if M does not halt on w, conclude that it will never accept and reject.”
Identify and clearly explain the flaw in their argument. Why is H not a valid decider?

Solution.
The flaw is in step 4. While simulating M on input w, if M never halts, then the simulation
also runs forever. The machine H has no effective way to detect, after finite time, that M
will never halt.
In more detail:
• If M accepts, then H can eventually see this and accept.
• If M rejects, then H can eventually see this and reject.
• But if M loops forever, H will also keep simulating forever.
The statement “if M does not halt on w, conclude that it will never accept” is exactly the
hard part. H is not a decider, because a decider must halt on every input. For inputs where
M loops forever on w, the machine H also loops forever and never reaches an accept/reject
decision.

Task 3.
Suppose we know that the Halting Problem is Turing-undecidable. Use reduction to prove
that the Acceptance Problem ATM is also Turing-undecidable.
Hint: Assume that ATM has a decider A. Show how to construct a decider for the Halting
Problem using A, and derive a contradiction.

Solution.
We prove this by reduction from the Halting Problem.

2

Assume, for contradiction, that ATM is decidable. Then there exists a decider
A(⟨M, w⟩)
that accepts exactly when M accepts w, and rejects otherwise. We will use A to decide the
Halting Problem
HALTTM = {⟨M, w⟩ | M halts on w},
which is impossible since we know HALTTM is undecidable.
Given an input ⟨M, w⟩ to HALTTM , construct a new Turing machine Nw such that:
Nw (x) ignores its input x, simulates M on w, and behaves as follows:
• If M ever halts on w (either accepting or rejecting), then Nw accepts.
• If M never halts on w, then Nw also runs forever.
Now consider the pair ⟨Nw , ε⟩, where ε is the empty string.
• If M halts on w, then Nw accepts ε, so ⟨Nw , ε⟩ ∈ ATM .
• If M does not halt on w, then Nw never accepts ε, so ⟨Nw , ε⟩ ∈
/ ATM .
Therefore, if we run the decider A on ⟨Nw , ε⟩, we can determine whether M halts on w:
• If A accepts, answer that M halts on w.
• If A rejects, answer that M does not halt on w.
This gives a decider for HALTTM , contradicting the fact that the Halting Problem is
undecidable. Hence our assumption was false and A does not exist.

Task 4.
Prove that the class of Turing-recognizable languages is closed under union.

Solution.
Let L1 and L2 be Turing-recognizable languages. We must show that
L1 ∪ L2
is also Turing-recognizable.
Since L1 and L2 are recognizable, there exist Turing machines M1 and M2 such that:
• M1 recognizes L1 ,
• M2 recognizes L2 .
This means:

3

• if w ∈ L1 , then M1 accepts w after some finite time;
• if w ∈
/ L1 , then M1 may reject or loop forever;
• similarly for M2 and L2 .
We now construct a recognizer M for L1 ∪ L2 .
On input w, machine M does the following:
1. Simulate M1 on w for one step.
2. Simulate M2 on w for one step.
3. Simulate M1 on w for one more step.
4. Simulate M2 on w for one more step.
5. Continue in this alternating way.
6. If either M1 or M2 ever accepts, then accept.
7. If both machines reject, then reject.
8. Otherwise continue the simulation (until both machines halt, or forever).
Why does this work?
• If w ∈ L1 ∪ L2 , then w ∈ L1 or w ∈ L2 .
• If w ∈ L1 , then M1 eventually accepts w, so during the “parallel” step-by-step simulation, M will eventually see that acceptance and accept.
• If w ∈ L2 , the same reasoning applies using M2 .
So every string in L1 ∪ L2 is accepted by M . If w ∈
/ L1 ∪ L2 , then neither M1 nor M2 ever
accepts w. In that case, M may reject (if both machines reject) or run forever which is allowed
for a recognizer. Therefore M recognizes L1 ∪ L2 , so the union of two Turing-recognizable
languages is again Turing-recognizable.
