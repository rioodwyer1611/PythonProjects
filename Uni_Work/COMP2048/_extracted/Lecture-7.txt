A different shape of computation
Every model we’ve met so far has been:
▶ Sequential: one step at a time
▶ Centralised: a single state, a single head, a single locus of
control
A cellular automaton is none of those:
▶ A grid of cells, each holding a value from a small alphabet
▶ No central controller; each cell only “sees” its immediate
neighbours
▶ Every cell updates in parallel, in lockstep, by the same local
rule
Simple local rules =⇒ rich global behaviour.
That sentence is the whole lecture.

What is a cellular automaton? (the picture)
▶ A grid of cells, each holding one of finitely many values.
▶ Each cell “sees” a fixed set of nearby cells: its
neighbourhood.
▶ A single local rule computes each cell’s next value from what
it currently sees.
▶ All cells apply the rule simultaneously, in discrete time steps.

Cellular automaton (formally)
A cellular automaton is a tuple (L, Σ, N, δ):
▶ L, the cellular space: a regular lattice, e.g. Z, Z2 , or a finite
grid.
▶ Σ, a finite state set: the values a cell can take.
▶ N, the neighbourhood: a finite set of offsets, fixing which
cells influence a given cell’s next value.
▶ δ : Σ|N| → Σ, the local rule: given the values in a
neighbourhood, returns the cell’s next value.
A configuration c : L → Σ assigns a state to every cell.
The global rule ∆ maps configurations to configurations by
applying δ at every cell in parallel.
“In parallel” is literal. All new values computed from the old
configuration, then updated at once.
6/39

Finite grids: what about the edges?
On an infinite lattice, ∆ is unambiguous. On a finite grid, a cell
near the edge is missing some neighbours. Three standard
conventions:
▶ Zero-padded (fixed): treat cells outside the grid as a fixed
background value, usually 0.
▶ Cyclic (wrap-around): in 1D, the line becomes a ring; in 2D,
a torus.
▶ Reflecting: mirror the grid at each boundary.
Boundary choice is part of the specification, not a detail.
The same rule on the same initial configuration can produce
qualitatively different long-run behaviour under different boundary
conditions. We will come back to this.

17/39

Class IV is rare, and Class IV is where it’s interesting
Out of 256 elementary rules, only a handful are Class IV. The
overwhelming majority of ECAs are I, II, or III.
Class IV sits right between:
▶ Class II (order): structure that freezes, loses all memory of
the input.
▶ Class III (chaos): structure that scrambles, any signal drowns
in noise.
Chris Langton (1990) named this in-between regime the edge of
chaos. We’ll return to it after the break.
And one more thing about Class IV.
Class IV is exactly where computation can live. Rule 110, on the
list above, is Turing complete. That is where we go next.

Rule 110 is Turing complete
Theorem (Cook, 1998 / 2004). Given any Turing machine M
and input w , there is an initial Rule 110 configuration whose
evolution simulates M on w .
Sketch (very): Cook showed
Rule 110 simulates cyclic tag systems, which simulate Turing
machines.
Particles are signals; collisions implement logic; the right initial
particle arrangement encodes any computation.
The actual construction is 40+ pages. We will not reproduce it.
We use it as a black box.
A 1D binary radius-1 rule is Turing complete.
That is astonishing.

A seemingly innocent question
Given a Rule 110 initial configuration c and a cell position i: does
cell i ever become 1?
Formally:
CELL = { ⟨c, i⟩ : cell i equals 1 at some time t ≥ 0 under Rule 110 from c }.

Theorem. CELL is undecidable.
In words: there is no algorithm that, given ⟨c, i⟩, always terminates
with the right yes/no answer.
We prove it by reduction from HALTTM : the same move from
last week’s lecture 6, just with a new target.

21/39

Reduction HALTTM ≤m CELL
Suppose for contradiction some TM D decides CELL. Build a
decider for HALTTM :
On input ⟨M, w ⟩:
1. Use Cook’s construction to build a Rule 110 initial
configuration cM,w and a distinguished cell position i ⋆ , such
that
cell i ⋆ becomes 1 ⇐⇒ M halts on w .
2. Run D on ⟨cM,w , i ⋆ ⟩.
3. Accept iff D accepts.
If D decides CELL, this procedure decides HALTTM .
But HALTTM is undecidable. ⇒ No such D exists. ■
A question about a row of bits updated by one XOR-like rule, that
no computer will ever answer.

Conway’s Game of Life
A 2D cellular automaton. Binary states, Moore neighbourhood
(the 8 surrounding cells, introduced earlier).
Rule B3/S23. For each cell:
▶ Birth: a dead cell with exactly 3 live neighbours comes alive.
▶ Survival: a live cell with 2 or 3 live neighbours stays alive.
▶ Death: every other cell dies (“loneliness” with 0 or 1,
“overcrowding” with 4+).
Invented by John Conway in 1970; popularised by Martin Gardner
in Scientific American that October. Still the most famous CA.
Three lines, two states. Deceptively simple.

Gosper’s glider gun

Emits one glider every 30 steps, forever.
Conway put up a $50 prize for any pattern of unbounded growth.
Bill Gosper’s team at MIT won it in November 1970 with this gun.
Glider gun = population grows without bound.
The gun is also the first step of the universality proof: a way to

26/39

Life is Turing complete
Gliders are the particles of Life: localised, moving, interacting.
Logic gates can be built from glider collisions:
▶ Two streams of gliders meeting at the right angle can
annihilate (AND-NOT).
▶ “Eater” patterns absorb stray gliders without getting damaged
(NOT).
▶ Guns supply glider streams on demand (signal source).
Wire enough of these together, with the right timing, and you get
a full Turing machine. Paul Rendell (2000) built a compact one;
later constructions have simulated specific Turing machines
running Life inside Life.
Class IV in 2D, same story as Rule 110 in 1D: simple local rule,
universal computation.

Can self-reproduction be formalised?
Living things reproduce. Can a machine?
John von Neumann (late 1940s, early 1950s) took the question
seriously. He wanted a mathematical model in which a machine
could build a copy of itself from raw materials on a uniform
“workspace.”
His answer, around 1952: a 2D cellular automaton with
▶ 29 cell states,
▶ von Neumann neighbourhood (introduced earlier),
▶ and a single configuration, hundreds of thousands of cells,
that copies itself.
Too large to simulate on the hardware of the time. Nobili and
Pesavento finally ran it in 1995, forty years after von Neumann’s
death.

The through-line
Every example today has had the same shape.
▶ Rule 90 (XOR in one line) ⇒ the Sierpinski triangle.
▶ Rule 110 (an 8-bit table) ⇒ a universal computer.
▶ Game of Life (rule B3/S23) ⇒ gliders, guns, logic gates.
▶ Langton’s loops (8 states, 86 cells) ⇒ self-reproduction.
Each local rule fits on a sticky note. Each global behaviour fills a
textbook.
That is emergence: structure that is not present in any single
cell’s rule, yet arises from running the rule everywhere in parallel.
One last question: can we predict, from the rule alone, which
regime a CA lands in?

Langton’s λ: one number per rule
For a binary CA, define
λ =

# neighbourhood patterns whose output is 1
.
# possible neighbourhood patterns

For an ECA (8-entry lookup table), λ ∈ {0, 81 , 28 , . . . , 1}.
Concretely, λ is the Hamming weight of the Wolfram number,
divided by 8.
Examples.
▶ Rule 0 = 000000002 : λ = 0. Everything dies.
▶ Rule 4 = 000001002 : λ = 1/8.
▶ Rule 30 = 000111102 : λ = 4/8.
▶ Rule 110 = 011011102 : λ = 5/8.
▶ Rule 255 = 111111112 : λ = 1. Everything becomes 1.
By 0 ↔ 1 symmetry, λ and 1 − λ give mirror-image dynamics. So
the informative range is λ ∈ [0, 0.5].

As λ grows from 0 to 0.5:

35/39

Computation at the edge of chaos
Langton (1990), “Computation at the edge of chaos.”
▶ Order (I, II) stores information but never moves it. No
computation.
▶ Chaos (III) moves information everywhere but scrambles it.
No computation.
▶ Edge (IV) does both: structures hold their shape and they
interact.
Consistent with everything we saw today:
▶ Rule 110 sits at the edge. Turing complete.
▶ Conway’s Life sits at the edge. Turing complete.
▶ Every other CA proved universal clusters here too.
A framework, not a theorem. Still, it unifies every visual we
watched today.
Rich computation does not live in boring rules, and does not live in
chaotic rules.
It lives on the boundary between them.

The same story in real brains
A spiking neural network (SNN): neurons fire discrete spikes
when their membrane potential crosses a threshold. Local rules,
parallel updates, discrete time (the same four ingredients as a CA).

Beggs & Plenz (2003) recorded spontaneous activity in cortical
slices and found neuronal avalanches: burst sizes following a power
law, the canonical signature of criticality. The middle regime is not
just a CA curiosity; it is what cortex actually does.

Many substrates, one sweet spot
Neuromorphic hardware: chips that run spiking dynamics
directly in silicon.
▶ Intel Loihi, IBM TrueNorth, SpiNNaker (Manchester).
▶ Tuning operating regime toward criticality is an active design
principle.
Langton’s edge of chaos, seen across today’s lecture and beyond:
▶ Elementary CAs (Rule 110): universal, at the edge.
▶ Conway’s Life: universal, at the edge.
▶ Cortex: neuronal avalanches at the edge (Beggs & Plenz).
▶ SNN reservoirs: computational capacity peaks at the edge
(Maass).
▶ Neuromorphic chips: tuned there by design.
▶ Deep neural networks: trainable only when initialised near
the edge.
One framework, six substrates. Rule 110 is not an exotic curiosity;
the phenomenon lives in your head (and inside every large model
you have heard of).
