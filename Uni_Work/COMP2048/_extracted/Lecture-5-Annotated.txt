The Tape and Head

One-sided infinite (to the right) tape divided into cells
(i.e., as much memory as needed)
Each cell contains a symbol from the tape alphabet
(e.g., = ⌃ [ {t})

blank

Head reads the symbol written on the current cell.

Head will move left (L) or right (R) after reading a symbol.
Initially:
Input string is placed on the tape.
The rest of the tape is blank (i.e., t).
Head starts on the leftmost symbol of the input.

Execution: Read-Write-State Transition-Head Move
1

Read the current symbol under head.

2

Apply transition function :
Write a (possibly new) symbol (from ) on the tape.
Move to a new state.
Move the head left or right.

3

Repeat 1 and 2 until:
The machine enters qaccept (immediately halt and accept).
The machine enters qreject (immediately halt and reject).
The machine never halts (infinite loop – also called “reject by
looping”).

Unlike previous models, TMs can accept/reject the input
by entering the accept/reject states at any time
(i.e., not exactly after reading the last symbol)

Common TM Design Patterns

1

Marking symbols (e.g., replace with X/Y)
Scanning left/right
Returning to the start
Matching pairs
Erasing / rewriting
Use subroutines (i.e., a group of states performing a task)
Remarks:
You can overwrite each matched 0 or 1 with a blank to “erase” it.
Make sure your TM doesn’t confuse these newly written blanks
with the originally empty cells beyond the input.
Can always add additional symbols to the tape alphabet to
avoid confusion (e.g, boundary markers, special symbols for
“erased 0”, “erased 1”, etc)
Usually it’s a good idea to initially verify if the input is in a valid
form (e.g., by checking a regex – no need to write on the tape)

History
1900 Hilbert’s Program
David Hilbert proposes 23 problems
Goal: Formalize all of mathematics (complete, consistent,
decidable)

1928 Entscheidungsproblem
Hilbert & Ackermann pose the decision problem
Is there an “algorithm” to decide truth of any statement?

1931 Gödel
Incompleteness Theorems
Any consistent formal system strong enough for arithmetic is
incomplete

1936 Church & Turing
Church: Undecidability via lambda calculus
Turing: Turing machines & Halting Problem
They essentially defined what an “algorithm” is (e.g., a TM)
Result: Entscheidungsproblem is unsolvable

Church-Turing Thesis
Church-Turing Thesis
Any function that can be computed by an “algorithm” can be
computed by a Turing Machine.
Not a formal theorem, but a widely accepted belief.
No counterexamples so far.
Equivalences:
-Calculus
Other models of computation (e.g., by Post, etc)

All major programming languages are Turing-complete
